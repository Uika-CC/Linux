# Linux 权限与共享目录管理

## 一、基本权限

### 普通文件

- `r`：读取文件内容。
- `w`：修改文件内容。
- `x`：执行文件，能否成功还取决于文件类型和执行条件。

### 目录

- `r`：查看目录中的文件名。
- `w`：增加、删除或重命名目录条目，通常需要同时具备 `x`。
- `x`：搜索、穿越目录，访问其中的条目。

**注意：修改文件内容主要看文件自身的写权限；删除或重命名文件主要看父目录的权限。**

## 二、用户、用户组与权限

一个普通文件或目录有一个所有者用户和一个所属组，传统权限位分别控制所有者、所属组和其他用户的访问权限。

管理共享目录时，需要考虑：

1. 哪些用户可以访问目录？
2. 用户能否读取、修改目录中的文件？
3. 新建文件应该归属哪个组？
4. 用户能否删除或重命名其他成员的文件？

## 三、SGID：继承目录所属组

为目录设置 SGID 后，在该目录下新建的文件和子目录通常会继承父目录的所属组。

例如：

```
sudo chown root:devteam /opt/team-share
sudo chmod 2770 /opt/team-share
```

其中：

- `root` 是目录所有者。
- `devteam` 是目录所属组。
- `2` 表示启用 SGID。
- `770` 表示所有者和所属组拥有读、写、执行权限，其他用户没有权限。

SGID 影响的是新建对象的**所属组**，不会自动改变其所有者，也不会自动授予组写权限。

## 四、Sticky Bit：限制删除和重命名

对于设置了 Sticky Bit 的目录，通常只有文件所有者、目录所有者或具备相应特权的用户，才能删除或重命名其中的文件。

典型用途是允许多人在同一个目录中创建文件，同时减少成员删除或重命名彼此文件的风险。

## 五、共享目录设计原则

- 用户组：决定哪些用户属于协作团队。
- 目录权限：决定用户能否访问、创建或删除目录条目。
- 文件权限：决定用户能否读取或修改文件内容。
- SGID：让新建对象继承目录的所属组。
- Sticky Bit：限制目录中条目的删除和重命名。

**核心：组管理解决成员归属，权限位控制访问行为，SGID 管理组继承，Sticky Bit 限制删除和重命名。**
