# Linux 磁盘与 LVM 扩容实战

## 一、Linux 存储的基本层次

Linux 中一块磁盘最终要让用户能够使用，通常会经过：

```
物理磁盘
↓
分区（可选）
↓
文件系统 / LVM
↓
逻辑卷（LV）
↓
文件系统
↓
挂载
↓
目录
```

使用 LVM 时：

```
磁盘
↓
分区 / 整盘
↓
PV（Physical Volume）
↓
VG（Volume Group）
↓
LV（Logical Volume）
↓
文件系统（XFS/EXT4）
↓
挂载点
```

核心关系：

- **PV**：LVM 能识别和管理的物理存储资源
- **VG**：把多个 PV 组成一个存储池
- **LV**：从 VG 中划分出来的逻辑存储空间
- **文件系统**：真正负责组织文件和目录
- **挂载**：把文件系统接入 Linux 的目录树

------

# 二、查看磁盘与存储结构

### 1. `lsblk`

查看磁盘、分区、LVM、挂载点之间的结构：

```
lsblk
```

重点：

```
NAME        → 设备名称
SIZE        → 大小
TYPE        → 类型（disk/part/lvm等）
MOUNTPOINTS → 挂载点
```

例如：

```
nvme0n1
├─nvme0n1p1 → /boot/efi
├─nvme0n1p2 → /boot
└─nvme0n1p3
  ├─rhel-root → /
  ├─rhel-swap → [SWAP]
  └─rhel-home → /home
```

可以用它快速观察整个存储拓扑。

------

### 2. `df -h`

查看**文件系统实际可用空间**：

```
df -h
df -h /home
```

注意：

```
lsblk → 看块设备 / LV 有多大
df    → 看文件系统实际有多大、用了多少
```

所以 LV 扩大后，如果 `df` 没变化，不一定是扩容失败，可能只是**文件系统还没有扩容**。

------

### 3. LVM 查看命令

查看 PV：

```
sudo pvs
```

查看 VG：

```
sudo vgs
```

查看 LV：

```
sudo lvs
```

# 三、实际练习：给 `/home` 扩容

原本：

```
nvme0n1  60G
└─nvme0n1p3
   └─VG rhel
      ├─root  37.2G → /
      ├─home  18.2G → /home
      └─swap   2G
```

新增一块：

```
/dev/sda  10G
```

目标：

> 把新的 10G 加入现有 LVM，并最终扩展 `/home`。

------

# 四、第一步：确认新磁盘

```
sudo fdisk -l /dev/sda
```

确认 `/dev/sda` 是新磁盘。

注意：

**磁盘不一定必须分区。**

LVM 可以直接使用整块磁盘：

```
/dev/sda
```

也可以使用分区：

```
/dev/sda1
```

------

# 五、第二步：创建 PV

```
sudo pvcreate /dev/sda
```

查看：

```
sudo pvs
```

例如：

```
PV             VG   PSize  PFree
/dev/nvme0n1p3 rhel 57.41g    0
/dev/sda            10.00g 10.00g
```

这里：

- `/dev/sda` 已经成为 PV
- `VG` 一栏为空，说明它**还没有加入任何 VG**
- `PFree` 表示 PV 中还有多少空间没有分配给 VG

------

# 六、第三步：把 PV 加入 VG

原本：

```
VG rhel
└── /dev/nvme0n1p3
```

执行：

```
sudo vgextend rhel /dev/sda
```

含义：

```
vgextend
→ 扩展 VG

rhel
→ 要扩展的 VG

/dev/sda
→ 要加入的 PV
```

查看：

```
sudo vgs
```

例如：

```
VG   #PV #LV  VSize   VFree
rhel   2   3  <67.41g <10.00g
```

此时：

```
/dev/nvme0n1p3 ─┐
                ├── VG rhel
/dev/sda ───────┘
```

新的 10G 已经进入 `rhel` 的存储池。

------

# 七、第四步：扩展 LV

查看：

```
sudo lvs
```

目标：

```
rhel-home
```

使用 VG 中全部剩余空间：

```
sudo lvextend -l +100%FREE /dev/rhel/home
```

含义：

```
lvextend
→ 扩展逻辑卷

-l
→ 按逻辑 PE 数量进行扩展

+100%FREE
→ 使用 VG 当前所有剩余空间

/dev/rhel/home
→ 要扩展的 LV
```

扩展后：

```
rhel-home
18.2G
 ↓
28.2G
```

此时可以：

```
lsblk
```

看到 LV 已经变大。

------

# 八、第五步：扩展文件系统

这里是一个非常重要的知识点。

LV 变大：

```
LV
18G → 28G
```

**不代表文件系统自动变大。**

之前实际出现过：

```
lsblk
rhel-home → 28.2G
```

但：

```
df -h
/home → 19G
```

原因：

```
LV 已经扩容
↓
XFS 文件系统还没有扩容
```

因为 `/home` 使用的是 XFS，所以执行：

```
sudo xfs_growfs /home/
```

然后：

```
df -h /home
```

最终：

```
/dev/mapper/rhel-home
29G
```

扩容完成。

------

# 九、整个扩容过程

最终完整流程：

```
新增磁盘 /dev/sda
        ↓
pvcreate /dev/sda
        ↓
PV
        ↓
vgextend rhel /dev/sda
        ↓
VG rhel 增加 10G 可用空间
        ↓
lvextend -l +100%FREE /dev/rhel/home
        ↓
LV rhel-home 扩大
        ↓
xfs_growfs /home
        ↓
XFS 文件系统扩大
        ↓
/home 真正获得新增空间
```

记住三个最关键的动作：

```
vgextend
→ VG 变大

lvextend
→ LV 变大

xfs_growfs
→ XFS 文件系统变大
```

# 十、为什么 `lsblk` 和 `df` 的容量可能不同？

这是这次实验最重要的理解之一。

```
lsblk
→ 关注块设备层

df
→ 关注文件系统层
```

所以可能出现：

```
LV：28G
文件系统：19G
```

这并不矛盾。

因为：

```
/dev/rhel/home
       ↓
     LV 28G
       ↓
   XFS 文件系统 19G
       ↓
      /home
```

执行：

```
xfs_growfs /home
```

之后：

```
LV 28G
↓
XFS 也扩展到约 28G
↓
/home 可使用空间增加
```

# 十一、挂载相关

创建文件系统以后，如果没有自动挂载配置，还需要手动挂载：

```
sudo mount /dev/xxx /mnt
```

查看当前挂载关系：

```
findmnt
```

查看块设备及挂载点：

```
lsblk
```

查看文件系统使用情况：

```
df -h
```

如果希望重启后自动挂载，需要配置：

```
/etc/fstab
```

系统启动时根据 `fstab` 自动完成挂载。

因此：

```
mount
→ 执行挂载

/etc/fstab
→ 定义持久化挂载规则

systemd
→ 系统启动过程中组织自动挂载
```

# 十二、这次实验形成的管理员思维

以后遇到：

> “服务器磁盘空间不够，新加了一块硬盘，怎么扩？”

不要直接想到某一个命令，而是先沿着存储链检查：

```
磁盘
↓
PV
↓
VG
↓
LV
↓
文件系统
↓
挂载点
```

每一层解决不同的问题：

```
磁盘不够
→ 添加磁盘

VG 没空间
→ 添加 PV / 扩展 VG

LV 不够
→ 扩展 LV

文件系统不够
→ 扩展文件系统

没有挂载
→ mount / fstab
```

**核心思想：Linux 存储扩容不是“一条命令”，而是逐层扩大资源。**
