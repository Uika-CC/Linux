# Linux 磁盘、分区、文件系统、挂载与 LVM

## 一、Linux 存储的整体关系

Linux 只有一棵目录树，根目录为 `/`。

磁盘、分区、文件系统、挂载分别解决不同的问题：

```
磁盘
 ↓
分区（可选）
 ↓
文件系统
 ↓
挂载
 ↓
Linux 目录树
```

如果使用 LVM，则中间增加：

```
磁盘 / 分区
     ↓
    PV
     ↓
    VG
     ↓
    LV
     ↓
文件系统
     ↓
挂载
     ↓
目录
```

------

## 二、磁盘（Disk）

磁盘是最底层的存储设备，例如：

```
/dev/sda
/dev/nvme0n1
```

Linux 可以识别磁盘，但**识别到磁盘 ≠ 磁盘已经可以直接作为普通目录使用**。

查看磁盘：

```
lsblk
```

------

## 三、分区（Partition）

分区的作用是：

> **把一块磁盘划分成多个独立的存储区域。**

例如一块 100GB 磁盘：

```
/dev/sdb
├── /dev/sdb1  60GB
└── /dev/sdb2  40GB
```

分区可以让不同区域独立管理、分别创建文件系统和使用。

### 注意

**分区不是必须的。**

如果一整块磁盘只准备作为一个文件系统使用，可以直接在整块磁盘上创建文件系统。

因此：

```
整块磁盘 → 文件系统
```

也是可以的。

分区主要解决的是：

> **如何划分和管理磁盘空间。**

它本身不会让磁盘容量增加。

------

## 四、文件系统（Filesystem）

文件系统负责：

> **组织和管理文件、目录以及存储空间。**

常见文件系统：

```
XFS
ext4
vfat
```

例如：

```
/dev/sdb1
   ↓
XFS
```

此时 `/dev/sdb1` 上已经有一个可以管理文件的文件系统。

------

## 五、挂载（Mount）

挂载的作用：

> **把一个文件系统接入 Linux 的目录树，使其可以通过某个目录访问。**

例如：

```
mount /dev/sdb1 /data
```

表示：

```
/dev/sdb1
   ↓
文件系统
   ↓
/data
```

之后访问：

```
/data
```

实际上就是在访问 `/dev/sdb1` 上的文件系统。

### 重要理解

挂载**不是复制文件**，也不是把磁盘“搬到”这个目录。

它只是建立：

> **文件系统 → Linux 目录树中的访问入口**

------

## 六、/dev 是什么？

`/dev` 是 Linux 中用于表示和访问设备的特殊目录。

例如：

```
/dev/sda
/dev/sda1
/dev/nvme0n1
/dev/nvme0n1p3
/dev/mapper/rhel-root
```

可以简单理解为：

> `/dev` 是各种设备的访问入口。

它不是“所有磁盘文件都存放在这里”。

例如 U 盘：

```
/dev/sdb1
```

只是 U 盘分区对应的设备文件。

如果挂载到：

```
/mnt/usb
```

那么真正访问 U 盘文件时使用的是：

```
/mnt/usb
```

------

## 七、目录不一定对应独立磁盘

这是 Linux 存储非常重要的概念。

如果：

```
/dev/sda1 → /
```

那么：

```
/home
/home/user
/data
/var
```

如果没有额外挂载，它们都只是 `/` 文件系统中的普通目录，共享 `/` 的存储空间。

但是可以单独挂载：

```
/dev/sdb1 → /home
```

此时 `/home` 就使用独立的文件系统。

因此：

```
/ 快满
/home 很空
```

是完全可能的。

因为它们可能属于不同的文件系统。

同样：

```
/home/data 满了
/home 还有很多空间
```

也可能发生，前提是 `/home/data` 被单独挂载了一个文件系统。

### 判断路径实际属于哪个文件系统

```
df -hT / /home /home/data
```

不要只看目录路径，要看它实际属于哪个文件系统。

------

# 八、/boot 和 /boot/efi

## /boot

`/boot` 通常用于存放启动 Linux 所需要的文件，例如：

- Linux 内核
- initramfs
- 启动相关配置

## /boot/efi

`/boot/efi` 通常是 EFI 系统分区（ESP）在 Linux 中的挂载点。

EFI 系统分区通常使用 FAT/vfat 文件系统，供 UEFI 固件和引导程序使用。

简单理解启动过程：

```
UEFI
 ↓
EFI 系统分区
 ↓
Bootloader
 ↓
Linux Kernel + initramfs
 ↓
Linux 启动
```

------

# 九、Swap

Swap 是 Linux 使用磁盘空间作为虚拟内存的一部分。

它不是 RAM，速度远慢于 RAM。

查看：

```
free -h
swapon --show
```

查看交换活动：

```
vmstat 1 5
```

其中：

```
si = 从 Swap 换入内存
so = 从内存换出到 Swap
```

Swap 可以缓解内存压力，但大量持续的 Swap I/O 通常意味着内存压力较大。

------

# 十、LVM

LVM（Logical Volume Manager）用于更加灵活地管理存储空间。

核心三层：

```
PV
 ↓
VG
 ↓
LV
```

## 1. PV —— Physical Volume

物理卷。

把磁盘或分区交给 LVM 管理。

例如：

```
/dev/sdb
/dev/nvme0n1p3
```

初始化后成为 PV。

理解：

> “这块存储空间归 LVM 管理。”

------

## 2. VG —— Volume Group

卷组。

把一个或多个 PV 的空间集中成一个大的存储池。

例如：

```
PV 100GB ─┐
PV 200GB ─┴→ VG 300GB
```

VG 中的空间可以：

```
已分配给 LV
+
暂时空闲
```

因此新加入一块硬盘后，可以先把空间加入 VG，不急着分配给具体用途。

------

## 3. LV —— Logical Volume

逻辑卷。

从 VG 的存储池中分配空间给具体用途。

例如：

```
VG 300GB
├── rhel-root 100GB
├── rhel-home 80GB
├── data       20GB
└── 空闲       100GB
```

LV 可以继续创建文件系统：

```
LV
 ↓
XFS
 ↓
挂载到 /data
```

------

# 十一、LVM 与挂载的关系

LVM 和挂载不是同一件事。

LVM：

> **负责管理和分配存储空间。**

挂载：

> **负责把文件系统接入 Linux 目录树。**

完整关系：

```
磁盘 / 分区
     ↓
    PV
     ↓
    VG
     ↓
    LV
     ↓
文件系统（XFS）
     ↓
挂载
     ↓
/、/home、/data
```

例如：

```
/dev/nvme0n1p3
        ↓
       PV
        ↓
   VG: rhel
        ↓
   LV: rhel-root
        ↓
       XFS
        ↓
       /
```

------

# 十二、为什么 LVM 灵活？

假设 VG 中有空闲空间：

```
VG
├── root  40GB
├── home  40GB
└── 空闲  20GB
```

如果 `/` 快满了，可以从 VG 的空闲空间中分配一部分给 root LV，然后扩展文件系统。

如果以后需要 `/data`，也可以从 VG 中创建新的 LV：

```
VG
├── root
├── home
└── data
```

因此 LVM 的核心思想可以理解为：

> **先把存储资源集中管理，再根据实际需求分配给不同的逻辑卷。**

------

# 十三、磁盘扩容时要区分不同层次

“磁盘变大”不是一个单独的操作。

可能涉及：

```
物理磁盘
 ↓
分区
 ↓
PV
 ↓
VG
 ↓
LV
 ↓
文件系统
 ↓
挂载点
```

具体需要扩展哪一层，取决于当前系统的存储结构。

例如：

- VG 已经有空闲空间 → 可以直接考虑扩展 LV。
- 底层磁盘增加了空间，但分区/PV/VG 尚未获得这些空间 → 还需要继续处理底层层次。
- LV 扩大了 → 文件系统通常还需要扩展，才能真正使用新增空间。

所以：

> **接入新硬盘 ≠ / 自动变大。**

> **挂载新硬盘 ≠ / 自动变大。**

> **只有把新增存储空间真正加入 / 所属的文件系统，/ 的容量才会增加。**

```
lsblk
```


# 十五、最重要的理解

不要死记命令，先记住这套关系：

```
磁盘
↓
分区（可选）
↓
PV
↓
VG
↓
LV
↓
文件系统
↓
挂载
↓
目录
```

其中：

**分区：** 划分磁盘空间

**PV：** 把存储交给 LVM 管理

**VG：** 把多个存储空间集中成一个存储池

**LV：** 从存储池中分配逻辑空间

**文件系统：** 管理文件和目录

**挂载：** 把文件系统接入 Linux 目录树

**目录：** 用户和程序访问文件的路径

核心思想：

> **目录的位置和文件实际使用的存储空间不是一回事。**

> **Linux 可以通过挂载，把不同文件系统接入同一棵目录树。**

> **LVM 则让底层存储空间能够更加灵活地进行集中管理和重新分配。**
