# RHCSA：网络与 SSH 基础

## 一、网络基础检查

### 1. 查看网络接口

```
ip addr
```

重点关注：

- 网卡名称，例如 `ens160`
- 网卡状态
- IPv4 / IPv6 地址
- 子网前缀
- MAC 地址

例如：

```
ens160
└── 192.168.227.146/24
```

### 2. 查看路由

```
ip route
```

重点关注：

```
default via 192.168.227.2 dev ens160
```

其中：

- `default`：默认路由
- `192.168.227.2`：默认网关
- `ens160`：通过哪个网卡出去

------

## 二、NetworkManager 与 nmcli

RHEL 使用 **NetworkManager** 管理网络。

### 1. 查看网络设备

```
nmcli device status
```

查看的是：

> **当前网络设备本身的状态。**

例如：

```
DEVICE  TYPE      STATE     CONNECTION
ens160  ethernet  已连接    ens160
```

这里的 `ens160` 是实际的网络设备。

------

### 2. 查看 NetworkManager 的连接配置

```
nmcli connection show
```

查看的是：

> **NetworkManager 保存的网络连接配置。**

可以简单理解为：

```
device
  ↓
实际网络设备

connection
  ↓
NetworkManager 对设备使用的配置
```

例如：

```
ens160（设备）
    ↓
ens160（connection）
    ↓
IP / 网关 / DNS / DHCP 等配置
```

------

## 三、DHCP 与静态 IP

图形界面中配置静态 IP，本质上和 `nmcli` 修改 NetworkManager 配置是同一件事。

例如将 `ens160` 配置为静态 IPv4：

```
sudo nmcli connection modify ens160 ipv4.method manual
sudo nmcli connection modify ens160 ipv4.addresses 192.168.227.200/24
sudo nmcli connection modify ens160 ipv4.gateway 192.168.227.2
sudo nmcli connection modify ens160 ipv4.dns 192.168.227.2
```

使连接重新生效：

```
sudo nmcli connection up ens160
```

常用配置项：

| 参数             | 作用            |
| ---------------- | --------------- |
| `ipv4.method`    | DHCP 或手动配置 |
| `ipv4.addresses` | IP 地址和前缀   |
| `ipv4.gateway`   | 默认网关        |
| `ipv4.dns`       | DNS 服务器      |
| `connection up`  | 重新激活连接    |

### 注意

静态 IP 不能随便填写。

需要根据当前网络的：

- 子网
- 网关
- 地址规划
- IP 冲突情况

选择合适的地址。

例如：

```
192.168.227.146/24
192.168.227.2
```

可以判断当前网络属于：

```
192.168.227.0/24
```

# 四、网络连通性排障

可以按照从近到远的方式逐层测试：

```
ping -c 3 127.0.0.1
ping -c 3 192.168.227.2
ping -c 3 8.8.8.8
ping -c 3 baidu.com
```

可以概括为：

```
127.0.0.1
    ↓
本机 TCP/IP 协议栈、回环

默认网关
    ↓
本机 → 局域网 → 网关

外部 IP
    ↓
本机 → 网关 → 外部网络

域名
    ↓
DNS 解析 + 外部网络
```

### 排障思路

如果：

```
127.0.0.1     ✅
网关          ❌
```

优先检查：

- 网卡
- IP 地址
- 子网
- 网卡状态
- 局域网连接

如果：

```
网关          ✅
外部 IP       ❌
```

说明本机到网关基本正常，可以进一步考虑：

- 默认路由
- 网关
- NAT
- 上游网络

如果：

```
外部 IP       ✅
域名          ❌
```

优先怀疑：

- DNS 配置
- DNS 服务器
- DNS 解析问题

因此可以记成：

```
127.0.0.1 → 本机
网关       → 局域网
外部 IP    → 出网
域名       → DNS
```

# 五、SSH 基础

SSH 远程连接的基本形式：

```
ssh user@server_ip
```

例如：

```
ssh uika@192.168.227.146
```

SSH 默认使用：

```
TCP 22
```

服务器端核心服务：

```
sshd
```

------

# 六、SSH 排障思路

SSH 连接失败时，不应该只盯着 `ssh` 命令本身，而应该沿着连接路径逐层排查：

```
客户端
   ↓
目标 IP
   ↓
网络 / 路由
   ↓
服务器网卡
   ↓
防火墙
   ↓
TCP 22 端口
   ↓
sshd
   ↓
SSH 身份认证
   ↓
登录成功
```

### 1. 检查 sshd 服务

```
systemctl status sshd
```

确认 SSH 服务是否正常运行。

也可以：

```
systemctl is-active sshd
```

------

### 2. 检查 22 端口是否监听

```
ss -tnlp | grep :22
```

`systemctl status sshd` 正常，并不代表一定能够建立 SSH 连接。

还需要确认：

> **sshd 是否真的监听了目标端口。**

------

### 3. 检查防火墙

```
firewall-cmd --list-all
```

查看当前 firewalld 区域中的：

- services
- ports
- interfaces
- sources

等配置。

如果 SSH 服务正常、22 端口正常监听，但远程仍然无法连接，防火墙是重要的排查方向。

------

### 4. 检查网络

```
ip addr
ip route
ping <网关>
```

确认：

- 网卡是否正常
- IP 是否正确
- 默认路由是否存在
- 是否可以到达网关

------

### 5. 查看 SSH 日志

```
journalctl -u sshd
```

如果服务启动失败、配置错误、认证异常等，可以进一步从日志寻找原因。

------

# 七、SSH 排障核心逻辑

不要只记命令，可以把 SSH 问题理解成：

```
能不能到服务器？
        ↓
能不能到 22 端口？
        ↓
22 端口有没有 sshd？
        ↓
sshd 是否正常？
        ↓
用户认证是否成功？
```

常见排查命令：

```
systemctl status sshd
ss -tnlp | grep :22
firewall-cmd --list-all
ip addr
ip route
journalctl -u sshd
```

# 八、本次学习的核心理解

本次重点不是记住大量命令，而是建立两条排障链。

### 网络

```
本机
 ↓
网关
 ↓
外部 IP
 ↓
DNS
```

### SSH

```
网络
 ↓
防火墙
 ↓
22 端口
 ↓
sshd
 ↓
认证
```

遇到问题时，从底层到上层逐步缩小范围，而不是直接猜原因。

> **RHCSA 的网络管理不仅是“会配置 IP”，更重要的是知道网络出了问题应该从哪一层开始查。**
